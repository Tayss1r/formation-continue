I want you to implement the **training execution phase after results publication** by introducing a **Cohort system** in the Continuous Professional Training platform.

This feature must be fully implemented in **both backend and frontend**, and it must be **visible and usable through the website interface**, not just implemented as backend logic.

Important constraint:

**Do NOT write or generate any database migrations.**
The migrations will be autogenerated later. Only implement the models, services, APIs, and frontend logic required for the new workflow.

All pages must continue following the **same visual style as the landing page**.

---

# OBJECTIVE

After the coordinator publishes the results of a call, the system must allow the coordinator to organize the **training phase** by creating a **Cohort**.

A cohort represents the group of admitted employees who will follow the training.

The cohort becomes the central entity connecting:

* the call
* the course
* the professors
* the employees
* the training sessions
* the training materials
* the attendance records

---

# STEP 1 — Create Cohort

In the Coordinator dashboard, add a section:

**Cohorts**

From this page the coordinator must be able to create a cohort linked to a call.

The cohort creation form must include:

* Cohort name
* Associated call
* Associated course
* Training start date
* Training end date
* Daily start hour (earliest session time)
* Daily end hour (latest session time)

These fields define the **training margin**.

Example:

Training period
March 1 → April 30

Allowed daily hours
09:00 → 17:00

These margins will control when professors are allowed to schedule sessions.

---

# STEP 2 — Assign Professors

After creating a cohort, the coordinator must be able to assign one or more professors to it.

Add a page or section:

**Assign Professors to Cohort**

The coordinator selects professors from the professor list and links them to the cohort.

Assigned professors gain access to that cohort in their dashboard.

---

# STEP 3 — Professor Session Scheduling

Professors must be able to schedule sessions for the cohorts they are assigned to.

Add a page in the Professor dashboard:

**My Cohorts**

For each cohort the professor can:

* view the training margin defined by the coordinator
* create training sessions
* edit sessions
* delete sessions

When creating a session, the system must enforce validation rules:

The session date must be between:

training_start_date and training_end_date

The session start and end time must be within:

daily_start_hour and daily_end_hour

If a professor attempts to create a session outside these limits, the system must reject it.

---

# STEP 4 — Dynamic Training Calendar

Employees who belong to the cohort must be able to see the training schedule.

Add a page in the Employee dashboard:

**My Training → Calendar**

The calendar must display all sessions belonging to the employee's cohort.

Each session should display:

* session title
* date
* start time
* end time
* location
* professor

The calendar should update dynamically when sessions are created or edited.

---

# STEP 5 — Course Materials

Professors must be able to upload training materials for the cohort.

Add a section:

**Cohort Materials**

Professors can upload files such as:

* course slides
* documents
* supporting materials

Employees must be able to view and download these materials from their training page.

---

# STEP 6 — Attendance

Each training session must allow the professor to record attendance.

Add an attendance interface in the Professor dashboard.

For every session, the professor should be able to mark employees as:

* present
* absent
* late

Employees should be able to view their attendance history.

---

# STEP 7 — Coordinator Monitoring

The coordinator must be able to monitor the cohort from the Coordinator dashboard.

The cohort page should display:

* assigned professors
* session list
* attendance statistics
* enrolled employees

This gives the coordinator full visibility over the training phase.

---
